# Установка Lazy to Text

[English](INSTALL.md)

Если система предупредила вас, прежде чем открыть приложение, с загрузкой всё
в порядке. На этой странице: почему появляется предупреждение, как всё равно
открыть приложение и как проверить, что файл собран именно этим проектом.

## Коротко

- Lazy to Text это открытый проект (MIT). Установщики на
  [странице релиза](https://github.com/aa-blinov/lazy-to-text/releases)
  собирает GitHub из помеченного тегом кода, по сценарию из
  [`.github/workflows`](../.github/workflows). Вручную их никто не собирает.
- macOS и Windows предупреждают, потому что установщики **не подписаны платным
  сертификатом**. Apple берёт $99 в год за сертификат и нотаризацию, которые
  убирают предупреждение. Windows требует сертификат подписи кода и доверяет
  новому файлу, только когда его запустит достаточно людей. У бесплатного
  проекта пока нет ни того, ни другого. У Linux такой проверки нет.
- Звук не покидает компьютер. Сеть нужна, чтобы скачать модель при первом
  выборе, и только если вы включите постобработку через облачного провайдера,
  чтобы отправить ему текст.
- Загрузку можно проверить за минуту: раздел [Проверьте скачанный файл](#проверьте-скачанный-файл).

## Проверьте скачанный файл

У каждого релиза есть `SHA256SUMS.txt` с SHA-256 каждого файла. Сравните
строку вашего файла с тем, что посчитает компьютер.

macOS (Терминал), в папке с загрузкой:

```bash
shasum -a 256 LazyToText-Desktop-<версия>-mac-arm64.dmg
```

Windows (PowerShell):

```powershell
Get-FileHash .\LazyToText-Desktop-<версия>-setup-x64.exe -Algorithm SHA256
```

Linux:

```bash
sha256sum -c --ignore-missing SHA256SUMS.txt
```

Длинные шестнадцатеричные строки должны совпасть полностью. Если нет, скачайте
файл заново и не запускайте этот.

Контрольная сумма показывает, что файл дошёл целым. Что он собран **сценарием
этого репозитория из этого тега**, показывает подтверждение сборки (нужен
[GitHub CLI](https://cli.github.com/)):

```bash
gh attestation verify LazyToText-Desktop-<версия>-mac-arm64.dmg --repo aa-blinov/lazy-to-text
```

При успехе команда завершается без ошибки (в терминале ещё печатает строку
«Verification succeeded»); файл, изменённый после сборки или собранный в другом
месте, завершается ошибкой. Чтобы увидеть, откуда файл, запросите подробности:
добавьте `--format json` и прочитайте `sourceRepositoryURI`,
`sourceRepositoryRef` (это тег) и `buildSignerURI` (сценарий).

## macOS

Только Apple silicon (M1 и новее).

### Что вы увидите и почему

При первом запуске macOS сообщает, что **Apple не удалось проверить, что
«Lazy to Text» не содержит вредоносного ПО**, или что приложение **«повреждено и
не может быть открыто»**. Приложение не повреждено. macOS проверяет у каждого
скачанного приложения подпись разработчика, нотаризованную Apple. Эта сборка
подписана «ad hoc» (подпись показывает, что файл не менялся, но не кто его
сделал) и не нотаризована: для нотаризации нужна платная программа Apple
Developer Program.

### Открыть всё равно

1. Откройте `.dmg` и перетащите **Lazy to Text** в **Программы**.
2. Откройте приложение из «Программ» один раз. macOS откажет, нажмите **Готово**.
3. Откройте **Системные настройки → Конфиденциальность и безопасность**,
   прокрутите до раздела **Безопасность** и нажмите **Всё равно открыть** рядом с
   сообщением о Lazy to Text. Подтвердите паролем или Touch ID, затем нажмите
   **Открыть**.

В macOS 14 и старше можно вместо этого нажать на приложение правой кнопкой и
выбрать **Открыть**. С macOS 15 этого способа нет, остаётся путь выше.

Если macOS всё равно пишет, что приложение повреждено, а SHA-256 вы уже
проверили, снимите с приложения отметку загрузки:

```bash
xattr -dr com.apple.quarantine "/Applications/Lazy to Text.app"
```

Делайте это только для проверенного файла: так вы говорите macOS больше не
считать приложение загрузкой.

### Два разрешения

Их запрашивает приложение, macOS само не напоминает.

| Разрешение | Зачем |
| --- | --- |
| Микрофон | Записывать вашу речь. |
| Универсальный доступ (Accessibility) | Для глобальных горячих клавиш и для нажатия Cmd+V в окне, в которое вы печатали. |

В **Настройках** приложения есть плашка, которая открывает нужный раздел
Системных настроек.

Подпись «ad hoc» значит, что macOS считает каждый релиз новым приложением и
после обновления просит оба разрешения заново. Если после обновления перестали
работать горячие клавиши, откройте **Системные настройки → Конфиденциальность и
безопасность → Универсальный доступ**, удалите Lazy to Text кнопкой «минус» и
добавьте снова (или выключите и включите). Сборка, которую вы сделали сами через
`scripts/setup-signing.sh`, сохраняет разрешения.

## Windows

### Что вы увидите и почему

Установщик и портативная версия показывают **«Windows защитила ваш компьютер.
Microsoft Defender SmartScreen предотвратил запуск неопознанного приложения»**,
издатель указан как **Неизвестный издатель**. Браузер может добавить, что файл
**«редко скачивают»**.

SmartScreen оценивает файл по сертификату издателя и по тому, сколько людей его
уже запускало. У этих установщиков пока нет сертификата, а у нового файла нет
истории, поэтому его называют неопознанным. Это не вывод о том, что файл вреден.

### Открыть всё равно

1. Если браузер блокирует загрузку, выберите **Сохранить** (в Edge: три точки
   у файла, затем **Сохранить**, затем **Всё равно сохранить**).
2. Запустите установщик. В синем окне SmartScreen нажмите **Подробнее**, затем
   **Выполнить в любом случае**.

**Портативная** версия это один `.exe`, который при каждом запуске
распаковывается во временную папку; окно появится то же самое. Берите её там,
где нельзя запускать установщик. Установщик стартует быстрее.

Если Microsoft Defender удалил файл, сначала сверьте его SHA-256 с
`SHA256SUMS.txt`. Совпадение значит, что это файл, собранный проектом: его можно
восстановить в **Журнале защиты** и сообщить Microsoft о ложном срабатывании на
[microsoft.com/wdsi/filesubmission](https://www.microsoft.com/en-us/wdsi/filesubmission).

У Windows есть и свой выключатель микрофона: если запись беззвучна, откройте
**Параметры → Конфиденциальность и защита → Микрофон** и разрешите доступ
классическим приложениям.

## Linux

В Linux проверки подписи нет, поэтому предупреждений об издателе тоже нет.
Сообщения, которые вы можете встретить, технические.

**AppImage** (`…-linux-x86_64.AppImage`):

```bash
chmod +x LazyToText-Desktop-<версия>-linux-x86_64.AppImage
./LazyToText-Desktop-<версия>-linux-x86_64.AppImage
```

AppImage нужен FUSE 2. Если запуск прерывается сообщением про `libfuse.so.2`,
установите его: `sudo apt install libfuse2` (в Ubuntu 24.04 пакет называется
`libfuse2t64`).

**Пакет для Debian и Ubuntu** (`…-linux-amd64.deb`):

```bash
sudo apt install ./LazyToText-Desktop-<версия>-linux-amd64.deb
```

Если `apt` пишет, что загрузка «выполнена без песочницы от имени root», значит,
файл лежал в вашей домашней папке. Предупреждение безвредно, установка идёт
дальше.

Глобальные горячие клавиши и нажатие вставки в Wayland могут вести себя иначе,
чем в X11, потому что Wayland ограничивает то, что приложение может слушать и
отправлять. Если они не работают, попробуйте сеанс X11.

Если приложение не запускается, откройте его из терминала, чтобы увидеть
сообщение, и [создайте issue](https://github.com/aa-blinov/lazy-to-text/issues)
с этим текстом.

## Почему установщики не подписаны и что изменит ситуацию

- **Нотаризация macOS** требует Apple Developer ID из программы Apple Developer
  Program за $99 в год (бесплатно для некоммерческих организаций, учебных
  заведений и госорганов). Сборочный конвейер уже подготовлен, см.
  [Notarizing the Mac build](../README.md#notarizing-the-mac-build). Это решение
  про деньги, а не про код.
- **Подпись для Windows** требует сертификата подписи кода. Открытые проекты
  могут подать заявку в [SignPath Foundation](https://signpath.org/terms) на
  бесплатный: тогда издателем будет указан SignPath Foundation, и заявку нужно
  одобрить.
- Пока этого нет, контрольная сумма и подтверждение сборки выше показывают, что
  файл подлинный, а эта страница объясняет, почему предупреждения ожидаемы.
