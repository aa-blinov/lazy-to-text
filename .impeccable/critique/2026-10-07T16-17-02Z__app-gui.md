## Design Specificity Verdict

**LLM assessment.** The visual language is specific; the interaction model is generic. The token system has teeth and four details could not be transplanted: the two-page drop zone whose dashed surface never disappears, the engine-pill/EP readout, the cache-delete confirm that names which sibling caches flip to Download, and the topbar Cancel that exists because NeMo's cold import deadlocks for 8+ minutes. But the screens are a five-item nav + search field + full-width-card column + table + form. Nothing encodes the one thing that makes this product itself: it is a hotkey app operated while looking at another window, and its primary object is a keystroke. The flagship screen named after the product's verb does not perform the product's core action. There is no wordmark in any of the six screenshots, `hero.png` is a near-duplicate of `models.png` (18 differing rows, all inside the sidebar status dot), and the sidebar's top 120 px is empty.

**Deterministic scan.** The detector cannot judge this target. `impeccable detect --json app/gui` returns `[]` because the directory walk accepts only `.css .html .js .jsx .less .scss .tsx` and skips `.qss .py .svg .qml .ui` — verified with a controlled experiment where a byte-identical `.qss`/`.css` pair reported findings only for the `.css`. Zero eligible files. Passing `dark.qss` explicitly yields 6 advisories (5 `design-system-radius`, 1 `design-system-color`), and **all six are false positives**: 24px, 7px and 4px radii and `rgba(245,158,11,22)` each have a literal counterpart in `DESIGN.md`'s `components:` block (22/255 = 0.08627, matching the documented 0.086). The rule validates against the base `rounded:` scale only and never reads per-component overrides. The 45 Python files (12,585 LOC) scanned explicitly with advisories on returned `[]`.

Structurally, `dark.qss` is a pre-render token template — 240 `{{...}}` placeholders and 4 literal colours in 28 KB, substituted by `theme.py:288-290` — so auditing hard-coded colours against that file is the wrong model. One blind spot worth recording: the colour and radius rules need CSS-property context, so a bare `BRAND = "#ff00ff"` in Python never fires.

**Visual overlays.** Not applicable and not attempted: this is a native Qt desktop app with no dev server and no browser surface. No user-visible overlay exists, and none is claimed. The fallback signal is Assessment A's pixel measurements taken from the shipped PNGs via `QImage`.

## Overall Impression

A competent, honest shell that a determined user can work with, in which the load-bearing interactions are under-served. Nothing is broken enough to call it a failure; almost nothing is finished enough to call it good. The single biggest opportunity: **the dictation loop ends in silence.** The overlay is the best 400 ms in the product, and then it hides and the paste lands in another application with no confirmation anywhere. The code already solved this and pointed it at the wrong surface.

## What's Working

1. **The two-page drop zone** (`transcribe_view._show_source`). Dashed surface, drag target and the 120 px invitation share one `QStackedWidget`, so loading a file removes the prompt without removing the target. The comment at `:381-390` shows why the obvious version failed — a fixed `setMinimumHeight(120)` is what kept the zone from ever yielding the screen. An earned interaction idea that could not be transplanted.
2. **Destructive-action copy throughout.** `_on_history_clear` names the object and the count; `_on_clear_clicked` names the outcome on *both* buttons (`"Clear logs"` / `"Keep logs"`). The model-delete confirm additionally warns which sibling caches will flip to Download. For an app whose History is the user's archive, that is the correct amount of ceremony.
3. **Reduce Motion done properly on both platforms.** `motion.py` calls `NSWorkspace.accessibilityDisplayShouldReduceMotion()` on darwin and `SPI_GETCLIENTAREAANIMATION` on win32, cached 2 s because the wheel path queries per notch, with a 90 ms reduced fade and zero travel. Combined with `setAccessibleName` on the permission banners — with a comment explaining why two identical "Grant access" labels are useless to a screen reader — the accessibility work is ahead of the visual work.

## Priority Issues

### P0 — The core loop ends in silence
**What.** After dictation, `RecordingOverlay.set_state` falls through to `idle` and hides. `ClipboardManager.deliver_transcription` pastes or copies and returns a bool that nothing renders. Fourteen `user_message` messages ("Transcribed: …", "Auto-pasting text…", "Recording cancelled!") are the intended confirmation, already written, already routed to the one view the user is not looking at.
**Why it matters.** The dictation user is looking at Word, not here. Their only question is "did it go in?" The app is the only component that knows the answer and the only one that says nothing — on the single action the product exists for. It is also the peak-end violation.
**Fix.** A fourth overlay state `delivered` carrying word count and a one-line truth — `"Pasted 42 words"` / `"Copied 42 words — press ⌘V"` — holding ~2 s. Separately, make `_format_record_html` honour `user_message` with brighter ink and a leading marker. No toast: the main window is usually hidden and toasts self-suppress when `host.isVisible()` is false.

### P1 — The Models view asks a question it cannot answer
**What.** 16 unscored full-width cards, 7 families, registry order, no recommended default at the top, and a subtitle the cards immediately contradict.
**Why it matters.** First decision a new user makes. A user who obeys the instruction picks the worst Russian WER on the page; the two largest cards are 2.40 GB and 2.00 GB.
**Fix.** Replace the subtitle with the true rule; sort so the active model leads with a `Recommended` pill; add a language facet (`All / Russian / English / Multilingual`) next to search; add a three-line fastest/most-accurate/smallest strip sourced from numbers already on the cards.

### P1 — The primary interaction is a text field with a guessable syntax
**What.** `_start_edit`, `_stop_edit`, `_ptt_edit`, `_cancel_edit` are plain `QLineEdit`s. The grammar (`ctrl+f2`, `right_cmd`, `right_alt`, `fn`) exists only in `setPlaceholderText`. An invalid value sets `invalid` + `setToolTip(err)` and still emits `save_requested`.
**Why it matters.** PRODUCT.md Principle 1 is "the keyboard is the main interface", and the most keyboard-shaped interaction is the one place the user must memorise a private grammar. The page says "Changes save automatically", the border turns red, and nothing else — the app reports a save it did not perform.
**Fix.** Make it a recorder: on focus clear to "Press a combination…", capture `keyPressEvent` into canonical form, render as key caps (`hotkey_cap()` already exists and is already used by the Transcribe empty state — reuse it). On rejection keep the border, add an inline reason line, announce via `setAccessibleDescription`, and suppress the save emit.

### P1 — Overlay geometry is a platform risk (verify on hardware first)
**What.** `_reposition()` pins the overlay top-centre at `margin_top = 28` px from `availableGeometry()`. On macOS that band sits inside the menu-bar strip and exactly where the notch is; the window is deliberately at `NSStatusWindowLevel`, so the menu bar wins any overlap.
**Why it matters.** This is the only feedback surface during the core loop, and it is `WA_TransparentForMouseEvents` and non-focusable — if the notch eats it there is no fallback anywhere. Flagged from code; Assessment A could not run the app to confirm.
**Fix (after hardware check).** Read `NSScreen.visibleFrame` so the menu bar is subtracted, then offset below the notch (`safeAreaInsets`). On Windows dock to the notification-area edge, where the eye already is for a tray app.

### P2 — History is a mouse-only archive
**What.** `_on_copy_clicked` returns silently when no row is selected, and `Copy` is always enabled and always the sage primary — including on an empty view. `history_view.py` has no `setDefaultAlignment` and no `Key_Return` handler.
**Why it matters.** On a fresh History tab the most prominent button does nothing and says nothing. DESIGN.md claims "nothing in the app is mouse-only" — the table is Tab-reachable, its actions are not. History is the archive of every dictation the user has made; the app that replaced their clipboard has no keyboard route into that memory. Headers are centred while every cell is left-aligned, which reads as two different tables.
**Fix.** `Enter` opens detail, `Cmd/Ctrl+C` copies the selected row, `Cmd/Ctrl+Shift+C` copies all. Disable `Copy` when `current_row() < 0`. Add `header.setDefaultAlignment(Qt.AlignLeft | Qt.AlignVCenter)`.

## Persona Red Flags

**Power user (60+ dictations/day).** The Models column is a scroll tax: 16 cards × ~213 logical px ≈ 3400 px in a 780 px viewport, sortable only by registry order. No shortcut reference anywhere — `Ctrl+1..5` and `Cmd+F` surface in no menu on either platform. In tray-only mode there is no keyboard route to anything at all, because `LSUIElement` means no menu bar until a window exists. The per-card inference panel is unreachable before the load it governs (`model_card.py:577`) — to make a 2.40 GB load cheap you must first pay for the 2.40 GB load. Deleting a cache shows no estimate of what comes back.

**First-timer.** Lands on the hardest screen: Models is the default view and the only one with a decision. No "just let me dictate" path. "Bigger is more accurate" is the first instruction read and it is wrong. The default sits 7th of 16, unmarked. Card copy is addressed to a peer engineer ("*we* keep it for the languages the Russian-only cards do not cover"), not to a buyer. The hotkey is not shown until Settings — where it is a text field with a placeholder — while the Transcribe empty state already renders a real key cap for the same binding. Nothing states that the window must not have focus.

**Long-audio proofreader.** ~140 characters per line, 1.9× the ~75 DESIGN.md sets, in the one surface where reading accuracy matters. "Edited" is appended as a bare string to the same muted line as the byte and word count, with no colour or weight — the exact moment provenance stops mattering, nothing on screen changes. A 40-minute file is a multi-minute wait behind a 4-second reassurance line, with no Cancel on that screen at all (Models has one for a load). The loaded file keeps its dashed drop-zone border, so a file that *is* loaded looks exactly like a target that is not.

## Minor Observations

- **Logs toolbar collision.** The "Show network logs" label sits 1 logical px from the Clear logs button (measured: label ends x=1940, button border begins x=1942 at 2x). History's equivalent gaps measure ~8.5 logical. Cause: `QCheckBox::indicator { width: 16px }` grows the painted label without growing the layout rect, so `header.setSpacing(8)` never materialises.
- **Topbar crowding.** `RAM10.4/32.0 GB` has no space, and the four meters use two different label/value gaps. GPU at 4% renders as a ~7 px dot that reads as an artefact.
- **Salience inverted.** The success-lime "Current model" pill is the highest-chroma object in the window, permanently, for the least actionable fact; and a busy CPU turns that same widget to the Delete-button red, so a loaded machine reads as an error.
- **All six screenshots are Windows captures.** `ctrl+f2`/`f3`/`f6` are Windows defaults and the GPU/VRAM blocks render only under NVML. The macOS experience — the platform PRODUCT.md treats as most constrained — is visually undocumented. `ResourceWidget.setFixedSize(460, 32)` also still allocates two blocks on macOS, so each bar is ~215 px rather than collapsing.
- **The sidebar has no surface of its own.** Measured sidebar `#1d2021` = page ground `#1d2021`, though `theme.py:57` documents `bg_secondary` as "cards, inputs, **the sidebar**". The rail reads as unmapped space.
- **Selected-state documented only in its focused variant.** Every published screenshot shows the sidebar pill as `#d5c4a1` (`accent_focus`), but `#SidebarList::item:selected` is `accent` `#83a598` — the plain mouse-selected state appears nowhere.
- **DESIGN.md has drifted.** It says "nine shipped models" in four places; there are 16 since `ccefe38`.
- **Inert code, correctly documented.** `_hf_warning` is permanently `None` and `refresh_hf_token_state` returns immediately (no model is actually gated); `_NO_ENGINE_TEXT = "Engine: —"` is defined but the code renders `"● —"`, which is also a colour-only state indicator naming the system's own 11 px weight rule.
- **A failure path writes to `/tmp`.** `recording_overlay._apply_mac_window_behaviors` swallows every exception into `/tmp/ltt-overlay.log`, so an overlay that never appears over a fullscreen app leaves no trace in an app that has a Logs view.

## Provocative Questions

1. **What if the app never opened Models by default?** The user already has a working default. If Models opened collapsed to the active card — one card, the recommendation, "15 others →" — the first decision disappears and the 16-card column becomes something you visit deliberately. Is that view there because it earns its place, or because it was the easiest screen to build first?
2. **What if the recording overlay were the whole product?** The user is never looking at the main window while dictating. Should the overlay become a persistent, quiet dictation surface — word count, live partial text, current model, last-paste status — and the window become an archive you visit on purpose?
3. **What if `user_message` were the backbone of the design system instead of a log field?** Fourteen call sites already mark the lines meant for humans and nothing reads them. Making that flag first-class — brighter ink, its own level, filterable, and the source of the `delivered` state — would unify "what the app is doing" with "what the app is telling you". Does the app then need a separate status layer at all?
4. **Is the 1100 px content column right for anything?** Comfortable for navigation, unreadable for the two places the app asks you to read. Would a comparison table beside the full card, or a max-width on the transcript, buy more than it costs?
5. **What would the window look like with nothing in it?** Topbar's left 460 px is a debug gauge hidden until a model loads, the sidebar's top 120 px is empty, the lower 60% is void. Redesigned outward from the dictation loop — what does the user need to know, and when? — would Models still need to be a tab?
